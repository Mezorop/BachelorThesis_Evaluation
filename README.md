# Bachelor Thesis Evaluation

This repository incrementally extends the `output_results.tsv` generated by
the speech-to-speech models. Each evaluation stage has exactly one Python file
and its own virtual environment. This avoids having to pin WhisperX, SacreBLEU,
and COMET to an artificial shared set of dependency versions.

## Pipeline

```text
output_results.tsv
  -> WhisperX + TTFA/End Offset
  -> Text BLEU
  -> ASR-BLEU
  -> COMET + ASR-COMET
  -> fully populated output_results.tsv
```

| Stage | Python file | Environment | Main columns added |
|---|---|---|---|
| WhisperX/Timing | `whisperx_timing/evaluate.py` | `whisperx` | `asr_transcription`, `ttfa`, `end_offset`, and word boundaries |
| BLEU | `bleu/evaluate.py` | `bleu` | `bleu` |
| ASR-BLEU | `asr_bleu/evaluate.py` | `asr-bleu` | `asr_bleu` |
| COMET/ASR-COMET | `comet_and_asr_comet` | `asr-comet` | `comet`, `asr_comet` |

All existing columns are preserved. Each stage atomically writes its results
back to the same TSV file. The computationally expensive WhisperX stage saves
after every row, skips rows that have already been processed successfully, and
can resume after an interrupted job. Additional status and error columns make
incomplete rows visible.

## Timing Metric Definitions

WhisperX aligns the known German source transcript with the source recording.
For the translated recording, ASR is performed first, followed by word-level
alignment of the recognized English transcript. This ensures that the start
and end times refer to target-language speech actually recognized in the audio
file.

The timestamps of both WAV files start at zero. Hibiki's
`output_audio_start_delay` shifts the target recording onto the source stream's
timeline:

```text
TTFA = output_audio_start_delay
       + target_first_word_start_in_audio
       - source_first_word_start

End Offset = output_audio_start_delay
             + target_last_word_end_in_audio
             - source_last_word_end
```

## Official Implementations

- WhisperX follows the official `load_model` -> `transcribe` ->
  `load_align_model` -> `align` workflow from the
  [WhisperX repository](https://github.com/m-bain/whisperX#python-usage).
- BLEU and ASR-BLEU use `sacrebleu.metrics.BLEU` from the
  [official SacreBLEU project](https://github.com/mjpost/sacreBLEU). The TSV
  values are sentence-level BLEU scores on SacreBLEU's 0-to-100 scale;
  `effective_order=True` prevents misleading zero scores for very short
  sentences.
- COMET and ASR-COMET use `download_model`, `load_from_checkpoint`, and `predict` in
  accordance with the
  [official COMET Python API](https://github.com/Unbabel/COMET#scoring-within-python).
  `src` is the German source transcript and `ref` is the English reference
  translation. For COMET, `mt` is the model's translated text; for ASR-COMET,
  `mt` is the WhisperX transcript of the translated audio file.

## Installation on VSC-5

After loading the same Python modules used by the SLURM job:

```bash
module purge
module load python/3.12.8-gcc-12.2.0-4y5tbpr

cd "$DATA/translationEvaluation"
./setup_environments.sh
```

The four evaluation environments are created directly under `$DATA/venvs/` as
`whisperx`, `bleu`, `asr-bleu`, and `asr-comet`. They are separate from the
existing Hibiki-Zero environment at `$DATA/venvs/hibiki-zero`. For a
site-specific PyTorch/CUDA installation, the packages in the WhisperX and COMET
environments can be adjusted before running the pipeline without affecting the
other stages.

## Running the Pipeline

Rows that have already been evaluated successfully will be reused:

```bash
sbatch evaluation_pipeline.slurm
```

The pipeline reads and updates
`$DATA/unchecked_model_results/hibiki_zero/output_results.tsv` and uses the
fixed model defaults defined by the evaluation scripts.

## Expected Input Columns

The TSV generated by `hibiki_zero_script.py` already contains:

- `path_to_original_audio`
- `original_transcription`
- `expected_translation_of_original_audio`
- `translated_text`
- `path_to_translated_audio`
- `output_audio_start_delay`

The evaluation stages add their result, status, and error columns as needed.

The audio paths must be valid on the compute node. WhisperX and COMET download
their model weights on the first run, so their caches must either be populated
in advance or be accessible from the compute node.
